Keera Agents

KI-Agenten in der Sandbox, die dein Team unterstützen

Keera Agents betreibt KI-Agenten für dein Unternehmen. Jeder Agent ist ein Assistent mit eigener Sandbox, eigenem Arbeitsbereich und eigenem Gedächtnis. Dein Team gibt ihm Arbeit in Microsoft Teams oder Slack, und jeder Modellaufruf läuft durch Keera Gateway.

Kostenlos starten Keera Gateway ansehen ➔

So funktioniert Keera Agents

Arbeit kommt über Keera Agents in die Sandbox eines Agenten, und jeder Modellaufruf geht durch Keera Gateway hinaus. Ohne Arbeit schläft ein Agent und belegt keine Rechenleistung.

Was Keera Agents kann

Jeder Agent hat Anweisungen, ein Modell, Tools und ein Monatsbudget.

Arbeit aus deinen Chats

Schreib einem Agenten in Teams, Slack oder Keera Chat. Er antwortet im selben Thread und weiss, was dort gesagt wurde.

Board und Zeitplan

Weise ihm eine Karte zu, und er schiebt sie auf Review, wenn er fertig ist. Oder lass ihn jeden Werktag um acht laufen und das Ergebnis in einen Kanal posten.

Deine Ordner

Er liest und schreibt in den Ordnern in Google Drive, OneDrive und SharePoint, die du verbindest, und legt los, sobald eine neue Datei ankommt.

Deine Repositories

In GitHub oder GitLab pusht er einen eigenen Branch und öffnet einen Pull Request, den ein Mensch prüft. Dein Main-Branch bleibt deiner.

Agenten unter deinen Regeln

Ein Agent ist kein Schlupfloch. Er folgt denselben Regeln wie die Person, der er gehört, und erreicht nur, was du verbindest.

Ein eigener Schlüssel

Jeder Modellaufruf läuft mit dem eigenen Schlüssel des Agenten durch Keera Gateway, im Namen seines Besitzers. Modellzugriff, Budgets und Audit-Log gelten wie für Menschen.

Eine eigene Sandbox

Keera Agents läuft auf deinem bestehenden Kubernetes-Cluster. Jeder Agent bekommt einen abgeschirmten Container oder eine eigene Micro-VM, und was er ausführt, bleibt darin.

Keine Geheimnisse drin

Die Sandbox des Agenten kennt kein Passwort für deine Chats, Laufwerke oder Repositories. Diese Aufrufe macht Keera Agents und prüft vorher, ob der Agent darf.

Du bestimmst, wer fragt

Nur sein Besitzer, alle in der Organisation oder die Personen, die du nennst. Alle anderen bekommen ein kurzes Nein. Verlässt der Besitzer die Firma, hält der Agent an.

Häufige Fragen zu Keera Agents

Das fragen uns Teams, bevor sie einem Agenten Arbeit geben.

Was behält Keera Agents von meinen Daten?

Was die Arbeit braucht: Gedächtnis und Dateien des Agenten in seinem Arbeitsbereich und das Protokoll jeder Aufgabe für 90 Tage, damit ein Mensch seine Arbeit prüfen kann. Keera Gateway speichert weder Prompt noch Antwort und trainiert nicht darauf; es hält nur die Anfrage fest - wer, wann, welches Modell - im Audit-Log. Wer einen Agenten löscht, löscht seinen Arbeitsbereich.

Was kann ein Agent in Keera Agents erreichen?

Nur, was du verbindest: Modelle und MCP-Server über Keera Gateway, die Chats, in denen er ist, seine Ordner und Pushes auf Branches, die mit keera/ beginnen. Seine Sandbox hat kein Passwort und kein Token für diese Dienste. Diese Aufrufe macht Keera Agents selbst, nachdem es geprüft hat, dass der Agent darf.

Wie passt Keera Agents zu Keera Gateway?

Keera Agents baut auf dem Gateway auf. Jeder Agent ruft Modelle mit eigenem Schlüssel im Namen seines Besitzers auf. So gelten Modellzugriff, Budgets, Filter und Audit-Log für ihn wie für einen Menschen, und jede Aufgabe erscheint im Gateway als eine Session.

Was unterscheidet Keera Agents von Hermes Agent oder OpenClaw?

Hermes Agent und OpenClaw sind Open-Source-Assistenten für eine Person, auf ihrem eigenen Rechner oder Server, mit ihren Schlüsseln und Konten. Das können sie gut. Keera Agents betreibt Agenten für ein ganzes Unternehmen: Jeder hat einen Besitzer, eine Regel, wer ihm Arbeit geben darf, und keine Passwörter für deine Dienste in seiner Sandbox. Jeder Modellaufruf geht durch Keera Gateway, innerhalb des Budgets und ins Audit-Log.
