Ce qu'est Keera Code

Un ensemble de modèles à poids ouverts qui écrivent du code, exploités sur des GPU suisses ou dans votre propre centre de données. Au-dessus, une API tout à fait ordinaire : ce qui parle à OpenAI aujourd'hui parle à Keera demain.

Les modèles

Des modèles à poids ouverts, taillés pour le code, exploités sur des GPU suisses. Choisissez par espace de travail - ou laissez la passerelle router : les petites modifications au modèle rapide, le raisonnement difficile au plus puissant.

Modèle Contexte Idéal pour
Keera Deep 256k Travail agentique sur de nombreux fichiers
Keera Swiss 128k Code et documentation en allemand, français et italien
Keera Fast 64k Complétion, tests, hygiène des commits
Votre propre fine-tune - Frameworks internes et code légataire

Keera Deep et Keera Fast sont dérivés de Qwen-Coder, Keera Swiss d'Apertus. Tous trois sont sous Apache-2.0 : vous pouvez télécharger les poids et les emporter.

Les fournisseurs hébergés - aujourd'hui les modèles OpenAI - passent par les mêmes politiques, mais tournent sur l'infrastructure du fournisseur et non sur des GPU suisses. Ils sont bloqués par défaut ; un tenant les ouvre par équipe et par classe de données, ou pas du tout. État : septembre 2026.

Là où vos ingénieurs travaillent déjà

CLI, VS Code, JetBrains et headless dans la pipeline - le tout via une base URL compatible OpenAI. Vos serveurs MCP, API internes et outils se déclarent par projet dans AGENTS.md.

Chaque token consommé par Keera Code passe par Keera Gateway : les mêmes politiques et le même journal d'audit que partout ailleurs.

Questions fréquentes

Ce que les équipes d'ingénierie nous demandent le plus souvent avant d'essayer Keera Code.

Mon code reste-t-il chez moi ?

Oui. Les modèles tournent sur des GPU suisses ou dans vos propres baies ; votre code y part pour l'inférence et revient. Il n'est pas conservé, la réponse du modèle non plus, et rien n'est entraîné avec.

Est-ce que cela tourne dans mon IDE ?

CLI, VS Code, JetBrains, headless dans la pipeline. Tout passe par la même base URL compatible OpenAI - pas de client maison, pas de nouveau SDK, pas de plugin à maintenir. Vous changez une URL de base et vous continuez comme avant.

Les modèles ouverts sont-ils assez bons ?

Pour le travail quotidien, oui : refactorings sur de nombreux fichiers, tests, migrations, revues. Sur le raisonnement le plus difficile, les grands modèles propriétaires gardent une avance - c'est pourquoi ils passent par la même passerelle et s'ouvrent par équipe et par classe de données. Nous ne prétendons pas que les poids ouverts gagnent partout. Nous prétendons que le choix vous reste.

Quel rapport avec Keera Gateway ?

Keera Code est un client, Keera Gateway est le point d'entrée par lequel passent ses requêtes : les mêmes politiques et le même journal d'audit que pour toute autre application d'IA de la maison. Vous pouvez commencer avec une équipe sur Keera Code et placer la passerelle devant le reste plus tard - ou l'inverse.
